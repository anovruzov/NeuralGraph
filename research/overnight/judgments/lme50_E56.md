## 5. Leak check

Grepped (case-insensitive) for `gold`, `has_answer`, `evidence`, `answer`:
- `git diff -- crates` (taken before commit c13d9eaa landed at 09:50 mid-audit): only flips the two `ExtractionConfig::default()` values to `true` (+ golden/test updates);
  no hit outside golden prompt text.
- `crates/neuralgraph-memory/src/service.rs` `apply_exp` (NEURALGRAPH_EXP parsing, lines 76-140): no hit. Tokens only set config fields.
- `crates/neuralgraph-memory/src/prompts.rs`: only the words "answered" / "previous answer" inside prompt text; `RECONCILE_NUMERIC_EXTRA` is
  generic ("different numbers ... choose UPDATE") and names no benchmark item.
- `crates/neuralgraph-memory/src/extraction.rs`: no `gold` / `has_answer` / `evidence`; `hyphen_ground` / `same_numbers` see only message text.
- Ingest never receives the question: `chat-memory-longmemeval` ingests histories only; context is built by
  `crates/neuralgraph-research/src/benchmarks/chat_memory_context.rs` from `question` only. `gold` and `has_answer` are read
  there once, AFTER retrieval, to write the diagnostic `evidence_retrieved` field, which `answer_eval.py` carries but never feeds to the
  prompt (prompt = date line + `context` block + question; `cascade` is empty so no routing).
- Judge sees gold by design; same judge, prompts and cache keys for both arms.
Result: no leak found. Two non-leak risks: (a) commit c13d9eaa made both switches default-ON (`extraction.rs` mtime 09:48,
binaries 08:51/08:52 predate it, so the E56 run used the env var, confirmed by the store evidence in section 3): any rebuild before
`lme_base2` finishes, or any future "base" run on a rebuilt binary, silently becomes E56 (and that commit message quotes the
unaudited "strict 42->60" headline; the audited figure is about +12 pts and the digit-vs-no-digit UPDATE bug ships with it); (b) base and E56 contexts were generated by
different invocations (`with_sources` true vs false), harmless with quotes off, and the context text format is identical.
