## First loss point

**Literal event (variant A): stage 6, the holder's answer step, on the loop's own question.** The event is intact and traceable through every stage before it (stages 1-5, 9: canonical record, root, queue disposition `new`, domain, single shard, memory, outbox, coordinator `document.ingested`). When the discovery loop asks, ana's holder retrieves the memory (`memory_count 1`) and the `answer_from_evidence` task returns `no_evidence`, because the loop's question is the fixed template `What recurring operational blockers related to operations.logistics have you recorded, and what caused them?` (`models/fake.py:draft_question`, `fake_rules` in `models/tasks.py`), which shares 0 content tokens with "Acme Freight shipment into Rotterdam slipped another 9 days" (the fake rule needs 2). The goal's words (Rotterdam, Acme Freight) are in the gap description and in the `draft_question` input, but the template drops them. Result: 4 `no_evidence` responses, 0 claims, 0 discoveries, both questions `retained_uncertain`.

Two qualifications that matter for how far this generalises:
1. The loss is produced by the deterministic fake provider's rules. The real `draft_question` task is given `goal` and `gap` (`discovery/engine.py:_ask_for_gap`), so a real model could write a question that names Rotterdam; this audit cannot tell whether it would. What the run does show regardless of the rule details: the A goal ended in state `waiting` with exactly two questions (one per candidate domain) and nothing further, i.e. one `no_evidence` round per domain closed the coverage question. From reading `LoopEngine.tick` (not from a run): `uncovered = [d for d in domains if d not in covered and d not in attempted]`, and `attempted` is every domain that already had a depth-0 gap question, whatever its outcome, so the loop does not re-ask a domain with different wording. Candidate domains come only from owner-declared holder domains or domains published at >= 5 records (g2).
2. Once a question carries the event's words, the event is not lost: step 8 shows the literal event answered, committed as a claim with the full chain, and a discovery of kind **hypothesis** (`independent_roots 1`, the gate needs 2). It reaches a committed discovery only as a hypothesis; it can become `supported` only with independent support from other roots (probe g: 3 roots -> supported).

**Variant B (event with words the fake rules match)** reaches a committed discovery without a loss: `ev_365745cce25ebc9a99c1` -> `claim_2f233c62e5e54204ab2f` (hypothesis) -> `disc_b21e11f5a313403cae9c` (hypothesis), provenance chain verified to `rec_e39007e2aa31989a58a0630a` / source object `1790674800.000100`.
