# neuralgraph-research

The research track of NeuralGraph: the LoCoMo retrieval engine, the coordination simulator and the benchmark
harnesses. Nothing here is needed to run the assistant (that is [`neuralgraph-memory`](../neuralgraph-memory/));
this crate depends on that one and never the other way round (`crates/neuralgraph-memory/tests/crate_boundary.rs`
enforces it). Commands to reproduce every published number are in
[`research/README.md`](../../research/README.md#reproducing).

The crate is a port of the Python research code the September 2026 campaign ran on (last commit containing it:
`eba2f370`). One Rust module per Python module, with the same names:

| Python | Rust |
|---|---|
| `NeuralGraph/research/retrieval/*.py` | `src/retrieval/*.rs` (Tesseract, stores, LSH, reranker, query router, dialogue linker, mega search, KG extractor, the neural-graph engine and `NeuralGraphService`) |
| `NeuralGraph/research/coordination/*.py` (+ `benchmark.py`, `scale.py`, `figures.py` from `13a1729`) | `src/coordination/*.rs`, binary `coordination` |
| `NeuralGraph/temporal_utils.py`, `NeuralGraph/llm_backend.py` | `src/temporal_utils.rs`, `src/llm_backend.rs` (both build on the memory crate's ports) |
| `research/benchmarks/runner.py` | binary `runner`, `src/benchmarks/runner.rs` |
| `research/benchmarks/two_agent_eval.py`, `retrieval_eval.py`, `call_center.py` | binaries `two-agent-eval`, `retrieval-eval`, `call-center` |
| `research/benchmarks/rescore.py` | binary `rescore` |
| `research/benchmarks/chat_memory_locomo.py`, `chat_memory_longmemeval.py` | binaries `chat-memory-locomo`, `chat-memory-longmemeval` (they drive `neuralgraph-memory` as a library) |
| `kg_extractor.py`'s `__main__` | binary `kg-extractor` |
| `NeuralGraph/tests/*.py` | `tests/*.rs` (same test names) |
| `retrieval/en_thesaurus.jsonl` | `data/en_thesaurus.jsonl` (override with `NG_THESAURUS`) |

Flags, environment variables, stdout and output JSON of every harness are the Python ones. One addition:
`runner` with `RETRIEVAL_ONLY=1` makes no model calls (embeddings from `EMB_CACHE_DIR`, identity rerank, no answers
or judging) and writes `research/results/scratch/<RUN_NAME>.json` with real `retrieval_metrics`.

## Python semantics the outputs depend on

The engine's rankings depend on exact float results and on Python/numpy behaviour, so the port reproduces them
explicitly rather than with the nearest Rust idiom:

- `src/numpy.rs`: numpy's float32 `dot`/`linalg.norm`/`M @ q` came from Accelerate on macOS (every numpy 2.x wheel
  links it); the crate calls the same routines there, so charges are bit-identical. numpy's pairwise
  `add.reduce` (and so `norm(axis=1)`) is reimplemented exactly on every platform.
- `src/pyrandom.rs`: MT19937 with CPython's `random.Random` seeding, `choice`/`shuffle`/`sample`, and numpy's legacy
  `seed`/`randn` (polar Box–Muller with the fused multiply-add numpy is compiled with). LSH projections and the
  coordination fixture depend on it.
- `src/pytime.rs`, `src/pyre.rs`, `src/retrieval/pytext.rs`, `src/benchmarks/pyharness.rs`: naive/aware datetimes,
  Python's `\w`/`\b`/`\s`, `str.format`, `str()`/`repr()`, argparse number parsing; the memory crate's `pycompat`
  covers `json.dumps`, `round`, float repr and string slicing.
- Python `set`s iterated in per-process hash order. Wherever that order reached an output, the Rust uses insertion
  order; it is one of the orders Python could produce, and the only one that is reproducible.

## Golden fixtures

`tests/golden/*.json` were recorded from the Python at `eba2f370` by the `gen_*.py` scripts that sat next to
them (with shared helpers `_reference.py`, `_engine.py`, `_ordered_sets.py`, `_retrievers.py`). They were removed
with the rest of the Python and are recoverable from git history:

```bash
git show 9fc96328:crates/neuralgraph-research/tests/golden/gen_tesseract.py
```

The generators extracted the reference Python from git, pinned the clock and uuids, and swapped Python's
hash-ordered sets for insertion-ordered ones where order reached an output, so each fixture is exact and
regenerated byte-identically under any `PYTHONHASHSEED`. Every test asserts exact equality; float32-BLAS values are
exact on the macOS machine that recorded the fixtures and compared with a tolerance elsewhere (`numpy::bitwise_numpy`):
Accelerate's last bits differ between Apple CPU generations, so CI (macOS, for Accelerate) sets `NEURALGRAPH_BLAS_TOLERANT=1`. **Fixtures change only deliberately**, in a commit that says why — never to make a test pass.

Two tests need the gitignored embedding and KG caches (`research/results/emb_cache/`, `kg_cache/`) and are
`#[ignore]`d; they re-derive the published numbers:

```bash
cargo test --release -p neuralgraph-research --test locomo_reproduction -- --ignored --nocapture
```

## What reproduces, and what cannot

- **Exact:** the `metadata.retrieval_metrics` of all ten committed result files in `research/results/`
  (`runner` with `RETRIEVAL_ONLY=1`); the H9 split tables and every combined-stack row of `two-agent-eval`
  except one (below); the `retrieval-eval` table except one cell (below); the judge-sensitivity Gemma and substring
  columns and `rescore count`; the LongMemEval 50-question sample (seed 1); all nine coordination artifacts
  (four JSON, five SVG) byte for byte against `research/coordination/artifacts/SHA256SUMS`.
- **Not reproducible in Python either:** `two-agent-eval`'s "KG: graph channel only" row and `retrieval-eval`'s
  `tesseract+graph` multi_hop/ALL r@50 depended on Python's set iteration order; the Python itself printed
  different values under different hash seeds (single_hop r@10 17.7 vs 18.1; ALL r@50 32.8–32.9). The Rust values
  (17.4; 32.8) are what the Python prints with insertion-ordered sets.
- **Model-dependent** numbers (accuracy under an LLM judge, extraction-based Track D numbers) need the model. On
  LM Studio (Qwen3.8-9B, temperature 0) the Rust and Python runners send identical requests and parse identical
  results; see the port's commit history for the spot check.

## Known differences from the Python

Each is documented at the code site. Python bugs were ported as the error Python raised, not fixed, except where
noted:

- `runner.cosine_topk` cached by `id(nodes)`, which CPython can reuse for the next conversation's list (the
  published hybrid run reproduces only with the intended per-list cache); the Rust keys the cache by the list.
- Request bodies carry `temperature: 0.0` where Python sent the integer `0` (same JSON number value).
- `serde_json` rejects `NaN`/`Infinity` in model output that Python's `json.loads` accepted; such replies take
  the parse-failure path.
- numpy's `argsort` order among exactly equal cosine scores was unspecified; ties keep list order.
- `kg-extractor` keeps the Python `__main__`'s stale default paths (it always failed with `FileNotFoundError`);
  `--dataset`/`--cache-dir` point it at `research/datasets/locomo10.json` and `research/results/kg_cache`.
- Python bugs kept as errors include: `InMemoryNeuralGraphStorage.save_node_with_dedup` with an LSH index
  (`TypeError`, wrong keyword), `NeuralRetriever` on temporal queries (`NameError`), `speaker_profiles`'
  import of a module that does not exist (`ModuleNotFoundError`, so `USE_SPEAKER_PROFILES=1` aborts as before).
- Python's `async` code that awaited nothing real is synchronous; model calls stay async. `asyncio.gather` is
  `join_all` on one task.
