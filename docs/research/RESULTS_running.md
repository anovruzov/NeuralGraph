## Phase 0 end-to-end, single_hop 282 q, gemma-4-e4b answer+rerank+judge, no leakage
- flat (original Tesseract retrieval): 183/282 = 64.9%. recall@10 39.4, recall@50 61.7.
  - gold present in final 15-memory context: 158 q -> 77.8% correct
  - gold absent from context: 124 q -> 48.4% "correct" (judge leniency + paraphrase; treat with caution)
  - => two levers of similar size: get gold into context (retrieval), and answer correctly when it is there (rerank/prompt).
## Phase A retrieval-only (1540 q, substring recall)
- H3 pair nodes: WORKS. embed+pairs recall@10 31.3->47.8, @50 51.4->60.3 (beats flat Tesseract 42.5/58.2). As back-fill on Tesseract: recall@all 62.2->65.4 (+3.2). Window-3 adds nothing. Report: H3_pairs.md
- H4 keyword formula: DOES NOT WORK (flat/negative; drops more gold nodes). Report: H4_H6_scoring.md
- H6 soft temporal penalties / no min_charge: NULL (±0.2). Embedding rescue (H6c): mixed, +multi_hop, -single_hop@10.
- Surprise: fusion weights ~uniform across the 4 stores; TemporalStore dominates top-10 for every category. Hard ceiling: 25.5% of single_hop golds are not a substring of any message.
- H9a per-agent memory split: WORKS, biggest retrieval gain so far. Routing the question to the named speaker's own store: tesseract single_hop r@10 39.4->46.8, multi_hop 46.8->50.3; pure embedding single_hop 25.9->46.8, multi_hop 35.1->52.8. Gold is spoken by the other agent only 2.9% of the time. Federating by charge is worse than pooling (charge scales not comparable).
- H9b speaker-swap probe: swapping the name RAISES pure-embedding recall (26.6->34.8) because a speaker's own name appears in 0.1% of their messages vs 33.4% of the other's. Identity must come from speaker metadata, not text. tesseract+speaker has the largest identity sensitivity (gap 22.5). Report: H9_two_agent.md
- H9 combined stack: BEST RETRIEVAL = tess_local+pairs (route to named agent's store, Tesseract top-50, append 30 pair-node hits from that agent). recall@all single_hop 69.5 / multi_hop 68.4 / open_domain 24.0 vs prior best 65.2/65.6/22.9. Controls show the gain is the pair representation, not the wider window. Pair nodes are a bad BASE (cost single_hop -5.7 @10) but a good back-fill.
- Phase 0 e2e single_hop (282 q, same judge): flat 64.9% (6.4 s/q) | hybrid 67.0% (8.2 s/q) | graph 66.7% (7.9 s/q). Graph and hybrid are within noise of each other (+2 over flat, 282 q => ~±3 pt CI). local_pairs run in progress.
- Phase 0 e2e single_hop: local_pairs (per-agent routing + pair back-fill) = 208/282 = 73.8% (r@10 46.8, r@50 62.8, 7.9 s/q). +8.9 pts over flat 64.9%. Largest end-to-end gain of the campaign; confirmed on all 282 single_hop questions.

- H1 listwise rerank (8 calls of 10 vs 80 pointwise calls): MIXED. accuracy 74 vs 78 (control), rerank latency -56% (3.3 s vs 7.4 s). Second pass hurts (72). Gold-in-final-context identical (71%): the reranker only reorders; retrieval decides. Keep pointwise for accuracy, listwise for latency. Report: H1_listwise_rerank.md

Post-rerank gold rank is bimodal (1-5: 52, 6-15: 15, 16-30: 4, absent: 29): widening adds no gold, and gemma gets distracted ("Not found" with gold present). NOTE: 72/100 "single_hop" questions are still routed LIST/AGGREGATION by the regex router. Follow-up worth testing: SMALLER context (10). Report: H2_context_size.md
- H7 LLM router (one Gemma call/q, 5 modes) vs regex cascade: DOES NOT WORK (null). single_hop 79 vs 78, temporal 76 vs 78 (100 q each, same ids); +110 ms/q. Regex already routes 97% of temporal to TEMPORAL (97% agreement). On single_hop routers disagree on 48% of ids yet tie (40 vs 39 on those ids). Surprise: regex sends 72% of single_hop to LIST/AGGREGATION (30-mem context), only 10% STRICT; LLM also prefers LIST (53%). Prompt choice barely matters; context size (H2) is the lever. Report: H7_llm_router.md
## Phase C
- N3 reply-only unpairing: DOES NOT WORK. Ship tess_local+pairs unchanged. Insight: under local routing, both-member unpair is the only channel for the OTHER agent's utterance to enter (14 of 23 lost questions had gold only in the other agent's message, e.g. "Nate's favorite trilogy" said by Joanna). Pair nodes always outrank their bare reply, so once pairs are indexed message nodes are dead weight as a base. Report: N3_replyonly_pairs.md
- H5 open-domain routing: WORKS. OPEN_DOMAIN_WORLD (context wiped) fires on only 2/96 open_domain q; the lever is hedged-question routing (likely/might/would...) to OPEN_DOMAIN_INFER plus a memories+world-knowledge prompt that forbids abstaining. open_domain 41/96 (42.7%) -> 55/96 (57.3%), +14 (17 wins/3 losses; ~4 wins are judge leniency toward longer answers). Retrieval untouched (gold-in-ctx 10% both). single_hop 100: 77 vs 78 (noise). Flags OPEN_DOMAIN_KEEP_CONTEXT=1 OPEN_DOMAIN_FORCE_INFER=2 OPEN_DOMAIN_INFER_WORLD=1. Report: H5_open_domain.md
- H5 merged into main runner/answering/tesseract (flags default off; capstone will set OPEN_DOMAIN_KEEP_CONTEXT=1 OPEN_DOMAIN_FORCE_INFER=1 OPEN_DOMAIN_INFER_WORLD=1)
- N1 smaller answer context: DOES NOT WORK. 15/30 = 78% -> 10/15 = 71 -> 10/10 = 71 -> 5/10 = 69 (same 100 single_hop ids). With H2 (30 -> 76, 50 -> 69) the sweep 5..50 peaks at 15/30. Distraction refuted: on the 60 q whose gold was already in the top 10, accuracy fell 91.7 -> 83-88%. Two loss channels: truncation drops 6-14 golds at ranks 11-30, and list-style golds (69/100 multi-part) lose their second mention (Q1: corroborating 'adoption agency' memory at rank 21). Answer latency halves (479 -> 190 ms) but e2e only -4% (rerank 7.4 s dominates). Report: N1_small_context.md
- N4 reranker/answerer sees the previous message ("pair" context): DOES NOT WORK. 100 single_hop ids, local_pairs: control 78 | RERANK_CONTEXT=pair 71 (1W/8L, rerank +1.1 s) | ANSWER_CONTEXT=pair 75 (3W/6L, identical memory set) | both 66. Gold-in-context flat (71/69/73/70%); acc-given-gold falls 88.7 -> 82.6/83.6/78.6. Pair context dilutes the pointwise score (a rank-1 score-3 gold dropped to score 1 next to its prompt) and the ~20 extra prev lines distract the answerer (H2 effect). The pair idea belongs in retrieval only; keep single-message rerank/answer prompts. Report: N4_pair_rerank.md
- H8 stronger ANSWER model only (qwen3.6-35b-a3b answers; gemma reranks+judges): DOES NOT WORK under the gemma judge, MIXED on inspection. 71 vs 78 (same 100 single_hop ids, local_pairs). Gold-in-context identical (71/100 loose, 100/100 agreement); acc|gold-in 56/71 vs 63/71, acc|gold-absent 15/29 both. Judge-free substring score goes the OTHER way (51 vs 45): qwen abstains more (Not found 15 vs 10, 11 of them with gold present) and lists longer answers; gemma judge credits 34 of gemma's own non-substring answers vs 22 of qwen's (same-model leniency). Answer latency 501->913 ms (+82%), e2e +4%, rerank unchanged; all three models coexisted, nothing evicted. Answer model is not the lever; N5 strict judge should rescore. Report: H8_answer_model.md
- N5 judge sensitivity: PAPER-GRADE. Same answers score 13.5 / 21.6 / 51.4 / 64.9% depending only on the grader (substring / strict Qwen / lenient Qwen / lenient Gemma). Retrieval gain (flat->local_pairs) survives every judge (+4.6..+11.3, p<=.01). H8 sign flips (-7 -> +4 under strict), H5 gain vanishes under strict (-1.0). Lenient same-family judge rewards longer, hedged, partial-list answers. Gemma vs strict: kappa 0.30. Report: N5_judge_sensitivity.md
