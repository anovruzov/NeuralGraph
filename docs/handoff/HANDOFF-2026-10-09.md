# Mycelic research handoff — 2026-10-09

Written for the chief research scientist. The live copy, with comment threads and a decision column, is the shared
doc "Mycelic research handoff — 2026-10-09"; this file is its snapshot at 07:00 UTC. Edits there win.

## Bottom line

**The theory has not failed. It has not been tested yet.** All five real-data replays ran lexical word-matching and
model-free count detectors. None of them ran a small model, Tesseract, NeuralGraph, the Mycelic fabric or the
questioning step.

**The test we did run was biased toward a negative.**

- The chance baseline counted each outcome's own after-the-fact alerts. That inflated the expected recall finds from
  20.30 to 38.64.
- At the complaint volume our own diagnostic measured, the detectors had no power: 0 of 270 planted pre-event ramps
  raised an alert.
- The data window cut off 68–81% of the complaints that came before each event.

**Correcting these does not produce a positive.** The corrected found counts sit at chance (recalls 16 vs 20.30
expected, p 0.58). So the honest verdict is "uninformative", not "refuted".

**The first real-data reading test failed the same way.** In reader-001, three small models read 150 real complaints
and every one scored predicate F1 0.000, against 0.434 for word-matching. Our post-processing discarded each answer
that typed the vehicle without resolving it to a pack id. The instrument measured itself, not the models.

**Tesseract ingestion works, but nothing downstream uses it.** All 5,882 of 5,882 LoCoMo messages became nodes.
Tesseract is wired to nothing in Mycelic, crashes on the only persistent storage, and ranks a message's exact text
first only 72% of the time.

The night plan below fixes the instruments first, then puts Tesseract on the path, then re-tests.

**Update after the night's runs (22:30 UTC).** With the reading instrument fixed, the small models were tested twice
on the same 150 real complaints, and both results are real negatives for site models on public text:

- **Open reading (R002, RESULTS run 7):** predicate F1 0.026, 0.178 and 0.218, against 0.434 for word matching.
- **The narrow question HQ actually asks a site (J001, RESULTS run 9):** balanced accuracy 0.500, 0.477 and 0.387,
  against 0.670 for the lexical judge. The largest model tells filed from unfiled components but answers "unclear"
  instead of "no" (decision 9).

Detection stays uninformative rather than refuted: with the corrected baseline the finds sit at chance, and the power
check shows the detectors could not see a signal of the measured size (`DIAG-E002.md`, `POWER.md`). The leakage scan
with a small model in the loop passed (RESULTS run 8).

**Generalization, measured (10 Oct, 04:43 UTC).** A pack drafter (`mycelic/collective/onboard/`) drafts a pack from an
export alone, learning its vocabulary from the export's own filed categories, with no code per field. Its
pre-registered test D002 passed all six criteria on public data:

- **Mine accidents (MSHA, five operators, a field no pack covered):** micro F1 0.559 [0.532, 0.586] on held-out
  2022-2024 records, against 0.344 for the best control.
- **Vehicle complaints (six makes):** 0.590 against 0.406 for the hand-built `pack/`.

The first rule, D001, crashed on MSHA's quoted fields before reading anything; that is its recorded result
(`CHOICE-D001.md`, `CHOICE-D002.md`). This is lexical reading against filed categories, not detection.

the theory. Rows 2–7 are why that pipeline could not pass even on data with a real signal. Six investigators found
these, and independent reviewers re-checked them against the code and the saved audits.

## Tesseract and NeuralGraph ingestion

Ingestion into NeuralGraph storage loses no messages. Retrieval through Tesseract has five defects, two of which block
a per-site deployment. The checks below ran offline on all 10 LoCoMo conversations. The real embedding server cannot
be reached from this sandbox, so they used the repo's deterministic hash embedder (`chat_memory/llm.py:201`). The
structural results do not depend on the embedder; the recall percentages may change with real embeddings.

| Check | Result | Verdict |
|---|---|---|
| Messages become nodes | 5,882 of 5,882 in 31 s | Works |
| Session date and YEAR_/MONTH_ tokens on each node | 5,882 of 5,882 correct | Works |
| Tesseract on SQLite, the only persistent store | `AttributeError`: SQLite storage has no `get_neighbors` | Broken; blocks per-site use |
| Exact message text as the query: is that message ranked first? | 433 of 600 (72.2%); top 10: 543; outside top 50: 18. Plain cosine: 599 of 600 | Broken: all 57 misses name a speaker, and the name match swamps the text |
| Query-type router | Sends 895 of 1,535 questions to "open", which has no store; 30.7% of gold evidence is in no store's candidate list | Broken |
| Router on cross-site questions ("rising across sites") | No marker fires; near-uniform weights (0.25 / 0.31 / 0.25 / 0.19) | Cannot route |
| Message dates | `created_at` is the wall clock (0 of 5,882 carry the message year); the computed date tokens are never read | Broken |
| No embedding server | Ingestion silently creates 0 of 20 nodes; an empty query embedding raises `ValueError` | Fails silently |
| dia_id, session index, image captions | Dropped; 37.9% of evidence points at image turns; 37 questions are answerable only from a caption | Missing |
| LoCoMo category labels | Categories 1 and 4 are swapped in `runner.py` | Wrong labels |
| Tests | No test calls Tesseract; the one service integration test is skipped and fakes its score | Untested |
| Latency per query | 272 ms at 600 nodes; 2.6 s at 5,882; 8.7 s at 20,000 (flat scan) | Too slow for a site with tens of thousands of records |

**After the fixes** (merge 61c893e; re-measured 2026-10-09 with the same hash embedder, 60 messages from each of the
ten conversations):
- SQLite has `get_neighbors`, and 600 of 600 queries return the same top 10 on SQLite as in memory.
- Exact message text as the query ranks that message first in 599 of 600 queries and in the top 10 in 600 of 600.
- 5,882 of 5,882 nodes carry dia_id, the session index and the message year in `created_at`; captions are kept.
- Missing embeddings stop ingestion with `EmbeddingFailureError` and a count; an empty query vector is handled.
- Categories 1 and 4 are named by their evidence counts, and result files record the judge that ran.
- `NeuralGraph/tests/test_tesseract_ingestion.py` adds 17 tests; the NeuralGraph suite passes 239.

Not changed: the query-type router, routing on cross-site questions, latency, and the wiring gap below. No harness
scores evidence recall by dia_id yet.

**The wiring gap.** Tesseract is the routing layer between a neural graph and the Mycelic fabric only in the design.
In the code it is wired to nothing:

- No module in `mycelic/` or `mycelic/collective/` imports it. It runs only in `research/benchmarks/`.
- The collective guard requires 64 modules to import with the standard library only, and Tesseract needs numpy. The
  fabric guard forbids `llm_backend`, which Tesseract's package loads eagerly.
- Collective conclusions are written to the collective store only. Nothing publishes them into the fabric's event
  log.
- The fabric's own retrieval is BM25 with no embeddings and no graph.
- As built, Tesseract scores one session at a time and normalises each store by its own maximum. Merging such scores
  across stores was measured worse than pooling (H9: −2.5 and −4.4 recall@10).
- One seam already has the right shape: `NeuralGraph/research/coordination` (TesseractCoordinator,
  NeuralGraphMemoryAdapter). It runs only with test stubs today.

**What J001 shows** (added after the run, 22:21 UTC; `CHOICE-J001.md`, Runs).

- **The task the product gives a site model fails on public text too,** not only open extraction.
- **The two smaller models do not discriminate:** a-0p5b says "describes the component" on 145 of 150 filed and 145
  of 150 unfiled components; a-1p5b on 138 and 131.
- **a-4b discriminates but will not say no:** yes on 97 filed and 37 unfiled; on unfiled components it answers
  "unclear" 94 times and "no" 19 times. The shipped rule turns unclear into `unknown`, which is never correct.
  Counting unclear as a refute would give 0.700, but that reading was chosen after seeing the answers and decides
  nothing (decision 9 below).
- **Judge calls are short:** median 1.0 to 1.5 s (a-0p5b), 1.4 to 3.2 s (a-1p5b), 6.0 to 9.0 s (a-4b) on runner CPUs.

**Why R001 is zero.**

- **The setup:** the vehicle pack's only entity type is `vehicle`, and the prompt says to copy the vehicle as written.
- **The drop rule:** `ModelExtractor.postprocess` drops an item whole when its type is set but its text is null, or
  when the text does not resolve to a pack id.
- **The reconstruction,** through the repo's own code: a reader that always types `vehicle` scores 0.000, with 10 of
  10 items dropped. The same predicates with both entity fields null score 1.000.
- **The limit:** the raw replies were not stored, so the run itself cannot confirm this. Whether small models can read
  real complaints is still unmeasured.

**main-001 in brief.**

- **X with the model** beat S and model-free R only on narrative-only patterns, which those two cannot see. No seed's
  lift interval excludes zero.
- **Each site alone** found as many patterns as the collective channel or more, at about five times the alerts.
- **E1 field F1** on generator text was 0.256, 0.527 and 0.707, all below the 0.80 kill line.
- **The G0 failure was a scanner false alarm.** The planted id `TE-002` matched the tail of the site path
  `g0/region-1/site-002` in HQ's store. It reproduces offline with no model. After the planter learned to avoid the
  run's own org strings, 1,000-record scans pass on three seeds. Re-run in the lab with a-4b (g0-001, RESULTS run
  8): 0 of 4,259 canaries crossed, positive control 884 hits: passed.

**Speed on real text** (unit wall time per record, server start included): a-0p5b 9.9–10.5 s, a-1p5b 20.5–21.7 s,
a-4b 35.2–38.9 s. Each model ran on a different CPU model, so the three are not directly comparable.

Full records: `docs/lab/RESULTS.md` runs 5 and 6, and `docs/collective/replay/vehicles/CHOICE-R001.md`.
